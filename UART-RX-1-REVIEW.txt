IMPLEMENTATION
src/uart_rx.rs owns one fixed receive queue. USART_RX reads the saved UCSR0A
status before UDR0 and treats any DOR0/FE0/UPE0 bit (mask 0x1c) as damage.
The main loop only pops queue events; HAL transmit remains unchanged.
USART0 RXCIE0 is enabled after HAL setup and before global interrupt enable.
No second UDR0 read path, receive formatting, model work or RX allocation.
The queue's UnsafeCell is inside avr_device::interrupt::Mutex. Every mutable
access is in interrupt::free; no reference escapes. ISR entry disables global
interrupts and its inner critical section restores that disabled state. Pop
masks interrupts only around a bounded queue operation, not command handling.
No nested interrupts are enabled; Timer0 behavior and MODEL_PERIOD_MS=100 stay.

FAIL-CLOSED RULE
On a hardware error or full queue, queued data is discarded and the ISR drops
input until a CR/LF with NO hardware error flags. A faulty delimiter cannot
restore synchronization. A clean delimiter that triggers software overflow
itself is sufficient for recovery. No parser runs on these discarded bytes.
At that boundary the queue schedules an error event BEFORE any subsequent
bytes. The main loop clears its partial 64-byte command and overlength state,
then replies only ERR, with no recovered request ID. This prevents partial
set power, Designer set/apply/reset and legacy commands from being executed.
Errors during sustained overload may coalesce; valid queued lines may also be
discarded conservatively. This is not retransmission, flow control or exactly
one reply per line during a damaged stream. If no valid delimiter arrives,
the receiver keeps discarding and does not execute a suffix as a new command.
Already completed valid lines are not rolled back by errors in later input.
Ordinary command handlers, reply formats and overlength syntax errors remain.

CAPACITY CHOICE
32 byte positions, 31 usable; one slot distinguishes full from empty. Two u8
indices and two bool flags add 4 bytes: the complete queue is 36 static bytes.
At configured 57600/8N1 that holds about 5.38 ms of continuous incoming bytes;
at HAL's nominal 58823.5 actual baud it is about 5.27 ms. UART-2 observed a
roughly 3 ms model step in the failing experiment. This supports starting at
32 slots while retaining SRAM. It is NOT a measured worst-case step bound.
The command buffer remains 64 bytes: the receiver need not hold a whole line
when main drains it concurrently. During long command processing the expected
request/response peer waits for the reply. Uncontrolled pipelining, catch-up
steps or longer stalls can still overflow 31 bytes; those cases fail closed.
Larger capacity is not justified without the next hardware measurements.

LINKED-CODE CHECKS (nightly-2025-04-27, original AVR Release/LTO)
USART_RX is __vector_18; vector address 0x48 jumps to it. Representative code:
  126a: lds r18, 0x00C0  ; UCSR0A status snapshot
  126e: lds r25, 0x00C6  ; UDR0, only reader in linked .text

The snapshot survives reading UDR0. No callback or competing reader intervenes.
The handler has no call/rcall/icall, formatting, heap, model work or loops.
Explicit masking of the ring index removes array-bounds panic calls from ISR.
SREG/zero register and used registers are saved/restored by AVR interrupt ABI.
No memcmp/bcmp/compare_bytes, allocator or f64 runtime symbols in ELF.
protocol.rs, decimal.rs, model revision, Cargo files and toolchain unchanged.

STACK AND ISR COST LIMITS
Direct-call heuristic: deepest main path 933 bytes, main entry return 2,
plus USART_RX 10 saved bytes + 2 hardware return bytes = 947. Timer0 uses
8 saved + 2 return = 10; interrupts do not nest, so use max(12,10), not sum.
The former analysis tool's fixed 10-byte ISR allowance must be corrected.
Main's largest observed frame/save weight is 649 bytes. Deepest call chain
still runs through ThermalPlant::new, sample_temperatures and float multiply.
No unresolved direct or indirect calls were reported by that heuristic.
This is not a certified maximum or hardware watermark; do not call 184 bytes
a guaranteed safe margin. AVR hardware stack measurements remain necessary.
An acyclic ISR control-flow walk with a conservative 4 clocks per emitted
instruction plus hardware entry/vector JMP gives <=231 clocks (~14.44 us at
16 MHz). This overestimates normal instruction costs; it excludes waiting for
another ISR/critical section/current instruction and is NOT measured latency.
